# Plan 01-03: In-Memory Multi-Format Upload Route, Client Canvas Downsampler, & Resilient Ingestion UI

## Objective
Implement the ephemeral, in-memory file parsing route handler (`/api/upload`) supporting PDF (`pdf-parse`), DOCX (`mammoth`), and image base64 conversion (JPG/PNG) with zero disk persistence and structured error codes. Build the resilient client-side ingestion interface: offscreen HTML5 canvas downsampling for images > 4MB (max 2048px, JPEG 0.82), pre-flight validation with dropzone animation and Sonner toasts, document metadata preview cards, and automatic fallback transition to a manual text paste textarea when files are unreadable or yield fewer than 50 characters.

<threat_model>
### ASVS L1 Threat Assessment

#### Trust Boundaries
- **TB-03 (Browser File Upload to Node.js Serverless Route)**: Binary file buffers transmitted via HTTP POST `multipart/form-data` cross from the client machine into the `/api/upload` route handler. Risks include malicious executable uploads, oversized payload Denial of Service (DoS), decompression bombs, memory leaks from unrevoked client object URLs, and server-side disk leakage violating zero-retention privacy mandates.

#### STRIDE Register
| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| **T-01-03** | Denial of Service / Tampering / Information Disclosure | `app/api/upload/route.ts` | High | Mitigate | Strict MIME type and extension whitelist (`.pdf`, `.docx`, `.jpg`, `.jpeg`, `.png`); hard 10MB payload size ceiling returning HTTP 413; pure volatile RAM `Buffer` operations with zero `fs` disk writes or temporary file caching (CORE-04); import `pdf-parse/lib/pdf-parse.js` directly to prevent ENOENT debug crashes; memory garbage-collected upon response completion. |
| **T-01-04** | Denial of Service | `lib/image-utils.ts` | Medium | Mitigate | Revoke `URL.createObjectURL(objectUrl)` in both `onload` and `onerror` handlers; reset `canvas.width = 0; canvas.height = 0;` after `toBlob` conversion to immediately release GPU buffer; constrain max dimension to 2048px at 0.82 JPEG quality, ensuring client output is < 2MB. |

#### Security Controls
- **ASVS V12.1.1 & V12.1.2 (File Upload Security)**: Uploads are parsed directly in memory buffers, validated against a strict MIME whitelist, and never executed or written to the filesystem.
- **ASVS V5.1.1 (Payload Size Limits)**: Request body size is capped at 10MB on server route, and images > 4MB are downscaled client-side.
- **ASVS V11.1.1 (Client-Side Resource Management)**: Object URLs and GPU canvas buffers are cleaned up immediately to prevent client memory exhaustion.
</threat_model>

## Tasks

<task id="01-03-01" type="auto">
  <name>Implement in-memory multi-format upload API route handler with zero disk persistence</name>
  <action>
1. Implement `app/api/upload/route.ts` running in Node.js runtime (`export const runtime = 'nodejs'`, `export const dynamic = 'force-dynamic'`) per D-01 and CORE-04:
   - Reads incoming `multipart/form-data` via standard Web API `req.formData()`.
   - Validates that `file` exists and enforces 10MB payload ceiling (`MAX_FILE_SIZE = 10 * 1024 * 1024`), returning `413 PAYLOAD_TOO_LARGE` if exceeded.
   - Reads file into volatile Node.js `Buffer.from(await file.arrayBuffer())` with zero filesystem calls (`no fs.writeFile`, no `/tmp` writes).
   - Validates MIME type and filename extension against approved whitelist:
     - **PDF** (`application/pdf` or `.pdf`): Uses direct subpath import `pdfParse` from `pdf-parse/lib/pdf-parse.js` to bypass ESM test runner bug. Handles encrypted/password-protected PDFs cleanly, returning `422 PASSWORD_PROTECTED`.
     - **DOCX** (`application/vnd.openxmlformats-officedocument.wordprocessingml.document` or `.docx`): Uses `mammoth.extractRawText({ buffer })` to extract text while preserving paragraph breaks. Handles corrupt DOCX archives with `422 CORRUPT_FILE`.
     - **Image** (`image/jpeg`, `image/png`, `.jpg`, `.jpeg`, `.png`): Converts buffer to base64 string (`buffer.toString('base64')`), setting `isImage: true` per INGEST-05.
     - **Unsupported formats**: Returns `415 UNSUPPORTED_TYPE`.
   - For text formats (PDF/DOCX), passes extracted text through `cleanText` from `lib/text-utils.ts` per INGEST-06.
   - Asserts extracted text length `>= 50` characters. If `< 50`, returns `422 EMPTY_TEXT` per D-02 and INGEST-07.
   - Formats response according to `UploadResponseSchema` from `lib/schemas/upload.ts` returning `{ success: true, data: { text, isImage, rawBase64, mimeType, fileName, sizeBytes, wordCount } }` per D-01.
2. Create test suite `tests/upload-route.test.ts` to test route behavior using mocked file requests:
   - Valid text extraction from mock PDF buffer
   - Valid text extraction from mock DOCX buffer
   - Base64 encoding for JPG/PNG image buffers
   - Rejection of files > 10MB (`PAYLOAD_TOO_LARGE`)
   - Rejection of unsupported types (`UNSUPPORTED_TYPE`)
   - Rejection of empty or scanned text < 50 characters (`EMPTY_TEXT`)
   - Rejection of corrupt files (`CORRUPT_FILE`)
  </action>
  <verify>
    <automated>npm test -- run tests/upload-route.test.ts</automated>
  </verify>
  <done>
    `app/api/upload/route.ts` successfully parses PDF, DOCX, and images in volatile memory with zero disk writes, adheres to `UploadResponseSchema`, and passes `tests/upload-route.test.ts`.
  </done>
</task>

<task id="01-03-02" type="auto">
  <name>Build interactive drag-and-drop dropzone with client canvas downsampler, metadata preview card, and fallback manual paste textarea</name>
  <action>
1. Implement client-side canvas downsampler `lib/image-utils.ts` per D-13 and INGEST-02:
   - Function `downsampleImage(file: File, targetSizeBytes = 4 * 1024 * 1024, maxDimension = 2048, quality = 0.82)`
   - If image `<= 4MB`, returns original file without re-encoding.
   - If image `> 4MB`, loads into `Image` via `URL.createObjectURL(file)`.
   - In `onload`, revokes object URL immediately to prevent memory leaks. Computes proportional aspect ratio dimensions clamping max(width, height) to 2048px.
   - Draws to offscreen `HTMLCanvasElement` and converts via `canvas.toBlob('image/jpeg', 0.82)`.
   - Resets `canvas.width = 0; canvas.height = 0;` to release GPU texture buffers.
   - In `onerror`, revokes object URL and rejects with descriptive error.
   - Returns `{ file: compressedFile, wasCompressed: true, originalSize, compressedSize }`.
2. Implement `components/upload/FilePreviewCard.tsx` per D-14:
   - Renders document icon based on MIME type (`FileText`, `Image`).
   - Displays file name, formatted file size, word count badge, and a compression badge if downsampled (e.g. "Compressed from 6.2MB to 1.4MB").
   - Includes a clear/remove button to reset upload state.
3. Implement `components/upload/ManualPasteArea.tsx` per D-16:
   - Renders a multi-line legal text textarea styled with slate borders and obsidian focus ring.
   - Live character counter and word counter.
   - One-click "Paste from Clipboard" button utilizing `navigator.clipboard.readText()`.
   - "Clear" button and prominent "Manual Input Mode" status badge.
   - Inline alert notification when switched automatically from a failed document upload per D-02.
4. Implement `components/upload/DocumentDropzone.tsx` per D-04, D-15, INGEST-01, INGEST-07:
   - HTML5 drag-and-drop zone with file picker fallback (`input type="file"`).
   - Accepted file types: `.pdf`, `.docx`, `.jpg`, `.jpeg`, `.png` up to 10MB.
   - Interactive drag-over feedback: dashed gold border glow (`#D4AF37`), 1.01 scale transform, smooth 150ms transition.
   - Pre-flight validation per D-04: intercepts unsupported file extensions (.exe, .zip, etc.) or files > 10MB before network call, triggering a Sonner error toast and dropzone shake animation (`animate-shake`).
   - Automatic canvas downsampling via `downsampleImage` when images exceed 4MB before dispatching to `/api/upload`.
   - Shows indeterminate/determinate progress indicator during upload and parsing.
   - On upload error or `EMPTY_TEXT` / `CORRUPT_FILE` / `PASSWORD_PROTECTED` response: displays contextual alert and automatically switches active tab to `ManualPasteArea` per D-02.
5. Wire `DocumentDropzone`, `FilePreviewCard`, and `ManualPasteArea` together in `app/page.tsx` using Radix `Tabs` to allow seamless switching between "Upload Document" and "Paste Text".
6. Create unit test `tests/canvas-downsample.test.ts` to test dimension calculation and compression threshold logic in `lib/image-utils.ts`.

## Must-Haves (Goal-Backward Verification)

### Observable Truths
- User can drag and drop a PDF, DOCX, or JPG/PNG onto the dropzone and see file metadata card with word count and file size upon upload.
- User attempting to drop an invalid file (.zip, .exe) or file > 10MB is blocked client-side with a Sonner toast and dropzone shake.
- Images > 4MB are automatically downscaled via client canvas to < 2048px before transmission.
- Corrupt or empty text uploads trigger an inline explanation and automatically switch the view to `ManualPasteArea`.
- User can type or paste legal text in `ManualPasteArea` with live word and character counts.
- `app/api/upload/route.ts` processes all files in memory with zero disk writes.
