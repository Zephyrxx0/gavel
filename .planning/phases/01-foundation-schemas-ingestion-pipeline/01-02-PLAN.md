# Plan 01-02: Domain-Modular Zod Schemas & Conservative Text Sanitization Pipeline

## Objective
Establish the domain-modular Zod schema library (`lib/schemas/*`) defining canonical enums, typed upload API envelopes, and future analysis contracts with defense-in-depth epistemic non-UPL `.describe()` directives. Simultaneously, implement the conservative legal text sanitization utility (`lib/text-utils.ts`) that strips null bytes and unprintable control characters, normalizes CRLF line breaks, and collapses runaway newlines while strictly protecting clause numbering, section titles, and indentation hierarchy. Validate all schemas and text processing via comprehensive Vitest unit test suites.

<threat_model>
### ASVS L1 Threat Assessment

#### Trust Boundaries
- **TB-02 (Untrusted Document Text & AI Output Interface)**: Data arriving from unvalidated documents (PDF, DOCX, user paste) and downstream LLM generation crosses into system logic. Dirty text could inject control characters or malformed payloads, and unconstrained schemas could produce prescriptive legal advice violating UPL regulations.

#### STRIDE Register
| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| **T-01-01** | Tampering / Information Disclosure | `lib/schemas/*` | High | Mitigate | Enforce strict canonical enums (`RiskLevel`, `ActionTiming`, `ActionType`, `InconsistencySeverity`) and explicit non-UPL directives embedded directly in `.describe(...)` annotations. Schema parsing rejects unexpected fields or invalid enum states. |
| **T-01-02** | Tampering | `lib/text-utils.ts` (`cleanText`) | Medium | Mitigate | Regex sanitization strips null bytes (`\x00`) and unprintable ASCII control characters (`[\x01-\x08\x0B\x0C\x0E-\x1F\x7F]`), normalizes CRLF and CR to standard `\n`, while strictly preserving legal indentations, Roman numerals, and numbered clauses. |

#### Security Controls
- **ASVS V5.1.1 & V5.1.2 (Input Validation Architecture)**: Input schemas enforce strict typing, canonical enum values, and structural validation.
- **ASVS V5.1.4 (Control Character Sanitization)**: Raw input text is stripped of null bytes and unprintable terminal control characters before processing.
</threat_model>

<task id="01-02-02" type="auto">
  <name>Implement conservative legal text sanitization and word/character count utilities</name>
  <action>
1. Implement `lib/text-utils.ts` with conservative sanitization per D-03 and INGEST-06:
   - `cleanText(input: string): string`:
     - Strips null bytes (`\x00`) and unprintable control characters (`[\x01-\x08\x0B\x0C\x0E-\x1F\x7F]`)
     - Normalizes Windows CRLF (`\r\n`) and classic Mac CR (`\r`) line breaks to standard Unix LF (`\n`)
     - Replaces single tabs (`\t`) with 4 spaces to maintain indentation structure
     - Collapses 3 or more consecutive newlines down to exactly 2 newlines (`\n\n`) to preserve paragraph separation while removing excessive blank spacing
     - Trims trailing whitespace on individual lines while strictly preserving leading indentation
     - Strictly preserves clause numbering (`Section 1.1`, `Clause 4(b)(ii)`), Roman numerals (`(i)`, `(iv)`), statutory citations, and bullet points
   - `countWords(text: string): number`: accurately counts words based on whitespace separation, handling empty/whitespace-only input cleanly.
   - `countCharacters(text: string): number`: counts clean character count.
   - `isValidLegalText(text: string, minChars?: number): boolean`: asserts cleaned text meets the minimum character threshold (default 50 chars).
2. Create comprehensive test suite `tests/text-cleaning.test.ts` asserting:
   - Null byte and control character removal without data corruption
   - CRLF and CR normalization
   - Paragraph break preservation (collapsing `\n{3,}` to `\n\n`)
   - Protection of numbered clauses (`1.1`, `2.3.4`), Roman numerals (`(ii)`), and indentation
   - Word and character counting accuracy on various legal excerpts
   - Minimum character threshold validation (< 50 chars returns false)
  </action>

  </verify>
