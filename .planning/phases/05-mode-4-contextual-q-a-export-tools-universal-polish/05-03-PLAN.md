# Plan 05-03: Universal Slide-in ChatPanel Drawer, Citations & Trigger FAB

## Objective
Build the client-side interactive Q&A assistant components: `ChatTriggerButton.tsx` (a floating action button docked at bottom-right with mobile safe-area protection) and `ChatPanel.tsx` (a responsive slide-over drawer on desktop and full-screen sheet on mobile). Grounded in active report context using `@ai-sdk/react` and `DefaultChatTransport`, the panel provides mode-specific starter prompt chips, streaming markdown rendering with `react-markdown`, gold monospace citation badges for `[Clause X: Title]` references, assistant response copying, and non-UPL compliance banners. Verify component behavior with Vitest tests in `tests/chat-components.test.ts`.

<threat_model>
### ASVS L1 Threat Assessment

#### Trust Boundaries
- **TB-01 (Untrusted AI Output Rendering Boundary)**: Streamed text from the model is parsed and rendered into client DOM elements. An adversarial or hallucinated model response containing malicious HTML or scripts could execute XSS.
- **TB-02 (Mobile Viewport & Accessibility Boundary)**: Mobile touch interactions and virtual keyboards can obscure the chat interface or render inputs inaccessible.

#### STRIDE Register
| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| **T-05-08** | Tampering / Cross-Site Scripting (XSS) | `components/chat/ChatPanel.tsx` | High | Mitigate | Use `react-markdown` to safely render markdown tokens into React virtual DOM nodes. Never use `dangerouslySetInnerHTML`. Custom citation parser only inspects regex bracket tokens without executing raw HTML |
| **T-05-09** | Denial of Service / Client State Flooding | `components/chat/ChatPanel.tsx` | Low | Mitigate | Enforce `maxLength={1000}` on the chat input textarea. Provide a "Clear chat" reset action in the drawer header that purges active message state and cancels ongoing streams |
| **T-05-10** | Usability / Mobile Keyboard Occlusion | `components/chat/ChatPanel.tsx` | Medium | Mitigate | Use `fixed inset-0` with `h-[100dvh]` and iOS safe-area bottom padding (`pb-[max(1rem,env(safe-area-inset-bottom))]`) on mobile so the virtual keyboard does not push the input offscreen |
</threat_model>
