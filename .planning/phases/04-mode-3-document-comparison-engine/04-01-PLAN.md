# Plan 04-01: Schema Upgrade & Dual-Document Comparison API Pipeline

## Objective
Upgrade `lib/schemas/comparison.ts` to support rich 3-bucket negotiation cards (Push Back, Accept As-Is, Flag for Lawyer) and quantitative favorability metrics (D-13, D-16, COMP-06), updating schema tests in `tests/schemas.test.ts`. Author legal non-UPL comparison prompts and prompt builders with XML tag encapsulation in `lib/prompts/comparison.ts`. Implement the backend API route at `app/api/analyze/compare/route.ts` featuring automatic >80,000 combined character threshold detection and concurrent two-pass clause extraction using Claude 3.5 Sonnet (COMP-02, COMP-07, D-10, D-11). Validate with comprehensive Vitest tests in `tests/analyze-compare-route.test.ts`.

<threat_model>
### ASVS L1 Threat Assessment

#### Trust Boundaries
- **TB-01 (Untrusted Client Input Ingestion)**: Request payload sent to `/api/analyze/compare` contains two unauthenticated legal documents (`docA`, `docB` or images). Attackers could attempt prompt injection, instruction evasion, or payload tampering.
- **TB-02 (External AI Model Boundary)**: Outbound requests to Anthropic Claude 3.5 Sonnet via Vercel AI SDK `generateObject`. Model outputs must conform strictly to typed Zod schema rules and never execute prescriptive legal instructions.

#### STRIDE Register
| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| **T-04-01** | Tampering / Prompt Injection | `lib/prompts/comparison.ts` | High | Mitigate | Isolate both document bodies inside separate XML tags: `<doc_a_to_compare>` and `<doc_b_to_compare>`. System prompt explicitly commands the model to treat all enclosed text as untrusted citizen facts. |
| **T-04-02** | Information Disclosure / Non-UPL Violation | `lib/prompts/comparison.ts` & Route | High | Mitigate | Enforce third-person objective comparative framing ("Document A shifts indemnification liability to...", "Document B specifies broader terms"). Explicitly prohibit prescriptive second-person counsel ("you should reject", "you must sign") per legal compliance rules. |
| **T-04-03** | Denial of Service / Memory & Token Exhaustion | `app/api/analyze/compare/route.ts` | Medium | Mitigate | Reject empty payloads or documents under 30 characters before calling AI provider. For combined documents > 80,000 characters, switch to two-pass extraction targeting 7 key clauses to avoid context window blowouts. |
| **T-04-04** | Information Disclosure / Stack Trace Leakage | `app/api/analyze/compare/route.ts` | Medium | Mitigate | Catch all exceptions, suppress raw internal node/network errors, and return sanitized JSON error envelopes with structured error codes (`CONFIG_ERROR`, `BOTH_DOCUMENTS_REQUIRED`, `DOCUMENT_TOO_SHORT`, `ANALYSIS_FAILED`). |
</threat_model>

1. Create `app/api/analyze/compare/route.ts`:
   - Declare config:
     ```ts
     export const runtime = 'nodejs';
     export const dynamic = 'force-dynamic';
     export const maxDuration = 60;
     ```
   - Check `process.env.ANTHROPIC_API_KEY` -> 500 `CONFIG_ERROR`.
   - Parse JSON request body: `{ docA, docB, labelA, labelB, imageA, mimeTypeA, imageB, mimeTypeB }`.
   - Validate presence: either `(docA || imageA)` AND `(docB || imageB)` must be present; otherwise return 400 `{ error: 'BOTH_DOCUMENTS_REQUIRED', message: 'Both Document A and Document B must be provided for comparison.' }`.
   - Validate text length: if text is provided, ensure `docA.trim().length >= 30` and `docB.trim().length >= 30`; otherwise return 400 `{ error: 'DOCUMENT_TOO_SHORT', message: 'Each document must contain at least 30 characters.' }`.
   - Two-pass logic:
     - Check `const isLargeDoc = typeof docA === 'string' && typeof docB === 'string' && (docA.length + docB.length) > 80_000;`
     - If `!isLargeDoc`:
       - If images present, use multimodal messages with Claude 3.5 Sonnet.
       - If text present, call `generateObject` with `ComparisonSchema`, `COMPARISON_SYSTEM_PROMPT`, and `buildComparisonPrompt`.
     - If `isLargeDoc`:
       - Run Pass 1 concurrently via `Promise.all([ generateObject({ model, schema: Pass1ExtractionSchema, system: PASS1_SYSTEM_PROMPT, prompt: buildPass1UserPrompt(docA, labelA) }), generateObject({ model, schema: Pass1ExtractionSchema, system: PASS1_SYSTEM_PROMPT, prompt: buildPass1UserPrompt(docB, labelB) }) ])`.
       - Run Pass 2: call `generateObject` with `ComparisonSchema`, passing stringified excerpts from Pass 1 into `buildComparisonPrompt`.
   - Return `{ success: true, data: result.object, isLargeDoc }` with HTTP 200.
   - Catch errors and return 500 `{ error: 'ANALYSIS_FAILED', message: error instanceof Error ? error.message : 'Comparison analysis failed.' }`.
2. Run test suite to verify route passes all checks.
  </action>
