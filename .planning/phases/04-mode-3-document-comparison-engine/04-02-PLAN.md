# Plan 04-02: Dual Document Intake Experience & Comparison Progress

## Objective
Build the client-side dual document intake system and comparison progress loader for Mode 3 at `/analyze/compare`. Implement `DocumentZone` wrapping the established ingestion primitives (`DocumentDropzone`, `ManualPasteArea`, `FilePreviewCard`) with customizable labels and independent lifecycle states (COMP-01, D-02, D-03). Construct `DualDocumentIntake` orchestrating both zones and guarding comparison execution until both documents are populated, featuring character counters and quick-start preset scenario cards (`ComparisonPresetCards`). Implement `ComparisonProgress` with 4-stage step progression and large document amber notification (D-04, D-07). Validate with automated unit tests in `tests/comparison-intake.test.ts`.

<threat_model>
### ASVS L1 Threat Assessment

#### Trust Boundaries
- **TB-01 (Client-Side File Ingestion Boundary)**: Files dropped or pasted into the dual zones. Client must enforce file type restrictions, client-side size caps, and handle parse errors gracefully.
- **TB-02 (Ephemeral Client Memory)**: Document texts and base64 strings must reside only in React component state. Zero persistence to browser disk, cookies, or remote databases.

#### STRIDE Register
| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| **T-04-05** | Information Disclosure / Persistent Data Leakage | `DualDocumentIntake.tsx` & `DocumentZone.tsx` | High | Mitigate | Keep document text in ephemeral React state (`useState`). Purge state completely when user clicks "Compare Another Pair" or navigates away. Never store in `localStorage`. |
| **T-04-06** | Denial of Service / Client Freezing | `DocumentZone.tsx` | Medium | Mitigate | Enforce maximum client text paste bounds and rely on established `/api/upload` endpoint for PDF/DOCX processing with server-side validation. |
| **T-04-07** | Client Desync / Race Conditions | `DualDocumentIntake.tsx` | Low | Mitigate | Maintain separate state hooks for Document A and Document B (`docA`, `docB`, `isUploadingA`, `isUploadingB`). Ensure submit button requires `!isUploadingA && !isUploadingB && hasContentA && hasContentB`. |
</threat_model>
