# Plan 02-02: Dossier Header, Executive Summary & Risk Scorecard

## Objective
Implement Layers 1 and 2 of the Document Decoder dossier: the `ExecutiveSummaryCard` (classification, signatory parties, plain-English summary) and the `RiskScorecard` with individual `ClauseCard` components (traffic-light filtering, High-risk first sorting, mono obligation pills, crimson high-risk emphasis, and Radix Accordion verbatim source text). Create the client component test suite in `tests/decoder-components.test.ts` to assert sorting, filtering, and copy compliance.

<threat_model>
### ASVS L1 Threat Assessment

#### Trust Boundaries
- **TB-01 (Client Presentation Layer)**: Displaying AI-generated text and original document excerpts in the DOM. Ensure plain-English interpretations remain objective and non-prescriptive, and verbatim legal text preserves exact characters without executing arbitrary HTML or script injections.

#### STRIDE Register
| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| **T-02-04** | Tampering / XSS | `ClauseCard.tsx` & `ExecutiveSummaryCard.tsx` | High | Mitigate | Render all AI-generated strings and verbatim contract excerpts as standard React children / text nodes (`whitespace-pre-wrap`), never using `dangerouslySetInnerHTML`. |
| **T-02-05** | Information Disclosure / Non-UPL | `ClauseCard.tsx` | Medium | Mitigate | Clearly label AI interpretations as "Objective Analysis Rationale", maintaining separation between plain-English summaries and binding source text. |
</threat_model>
